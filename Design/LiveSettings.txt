Wakecup live settings

Current behavior
- The same settings are available while Wakecup is off or running. The header shows when the active timer ends.
- The When to stop card uses a date and time, the 1/3/5-hour presets, or Indefinitely. The calendar allows today and the next 30 local calendar days. Editing the selection does not change an active timer until Apply.
- During a run, the end time, battery permission, charge threshold, closed-lid mode, and display mode share one draft with Apply and Cancel at the bottom of the panel. Backlight off starts a visible 10-second countdown. Display changes preserve the running timer. The selected power policy can stop Wakecup if its conditions are no longer met.
- Open the lid before changing closed-lid mode during a run. Wakecup preserves the original end time or indefinite mode during the internal handoff.
- See ../README.md for the current user flow and DisplayModes.txt for the backlight design and verification history.

History
The following plan and verification notes describe the versions tested on their stated dates.

Original approved behavior (2026-11-07)
- One settings screen while off or active; active state adds the current timer and Stop.
- Display, battery permission and battery threshold apply without restarting the timer.
- The duration editor describes remaining time from Apply, not the original total duration. Editing alone does not alter the running timer.
- Closed-lid changes may restart the internal mode. Preserve the absolute continuous-clock deadline, including time spent restoring/authorizing; preserve infinity.
- Do not revive an expired timer. Confirm sleep restoration and prior guardian exit before starting a replacement guardian.
- Require the lid to be open for a closed-lid transition, avoiding unintended sleep during the handoff.
- Helper installation/removal stays blocked while active. Permission-mode selection may affect the next launch without restarting current work.
- Errors show what remains applied. No silently replayed privileged starts and no global power/security preference changes in tests.
- Backlight-off remains a separate deferred feature, pending its physical brightness-down test.

Original implementation plan (2026-11-07)
1. Core/SessionCore.swift and System/Guard.swift: optional absoluteDeadline in configuration, revisioned live settings in control, optional acknowledgement/effective policy in status. Validate before applying; keep old policy on rejected updates. Use revisioned updates for every deadline change.
2. Application/SessionModel.swift: explicit setters and runtime acknowledgement tracking; remaining-time drafts with Apply; restart request carrying the original deadline and an ordered stop/wait/start lifecycle. Keep system assertions during a safe handoff. Inject lid/guardian-liveness reads in SessionOperations for tests.
3. Presentation: always show SessionOptionsView, bind settings through explicit setters, disable only unsafe transitions, show Apply and pending/error state inline. Keep one display toggle, no duplicate active summary card. Timer remains visible during an internal restart.
4. Tests: Core acceptance/rejection, non-revival, timer replacements, repeated updates; fake model tests for live changes and rollback, finite/infinite restarts, expiry during authorization, guardian-exit waits, stale callbacks and no extra authorization. Offscreen EN/RU unified layout checks with isolated preferences.
5. Verify signed build, headless tests and selected offscreen tests; fresh focused review. Do not install over the user's active guardian; do not commit/push/tag/release.

Cross-module contract at the time (2026-11-07)
- SessionLiveUpdate: revision UInt64, powerMode PowerMode, threshold Int, deadline TimeInterval? (nil means infinity).
- SessionConfiguration.absoluteDeadline: optional TimeInterval, defaults nil for old records.
- SessionControl.update: optional SessionLiveUpdate.
- SessionMonitor: settingsRevision UInt64, settingsError String?, effectivePowerMode PowerMode, effectiveThreshold Int. settingsRevision means latest processed update, even if rejected; old/equal revisions never reapply.
- SessionStatus: optional settingsRevision UInt64, settingsError String, powerMode PowerMode, threshold Int. Existing deadline stays authoritative.
- UI model API: setClosedLid(Bool), setAllowBattery(Bool), setThreshold(Double), applyDuration(), durationEditDirty, settingsApplying, settingsMessage, isRestarting, canEditSessionSettings, canChangeClosedLid.
